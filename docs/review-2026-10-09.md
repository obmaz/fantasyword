## 코드 재리뷰

- 저장 키와 직렬화는 `DB_STORAGE_FIELDS`에 모아 일반 저장과 구매 저장의 규칙이 어긋나지 않게 했다. 기존 `v7_*`·단어장 ID·아이템 ID는 유지한다.
- 묶음 저장은 변경 전 값을 모두 읽고 성공 후에만 메모리/화면 상태를 적용한다. 실패하면 이미 쓴 키를 역순으로 복원하고 신규 키를 제거한다. 성공 보상 뒤 진행 저장만 실패한 상자는 재로드·재입장 시 보상 없이 진행을 복구한다.
- localStorage의 묶음 처리는 실패 복원이며 프로세스 강제 종료까지 보장하는 다중 키 트랜잭션은 아니다. 저장소 자체가 막혀 복원도 불가능하면 경고를 유지한다.
- 총공세의 이동 계산을 입력/프레임에 공유한다. 도착선의 `hit`는 이미 검사한 시각을 재사용해 미세하게 증가하는 실제 시계에서도 재귀 호출이나 이중 이동/생명 차감이 발생하지 않는다. 매 호출 증가하는 시계로 회귀 검증했다. 종료·세션 교체·늦은 콜백 차단을 유지한다.
- 상세 포커스 복원 대상은 헤더의 닫기 버튼으로 한정해 숨겨진 상세 X를 다시 선택하지 않는다. 연습 필터의 보조기술 상태와 빈 화면 문구를 함께 맞춘다.
- classic script와 CSS 적용 순서, 이미지 기반 UI, 세로 프레임, 역할별 모듈 경계를 유지했다. 무관한 전면 구조 변경은 하지 않았다.

확인한 범위에서 미해결 P1~P3는 없다. 주변 서비스의 전역 연결, 큰 CSS cascade, 연습/발음 경로만 대상으로 한 strict 타입 검사는 구조 제약으로 남아 있다. 설치 음성/원격 TTS 가용성도 환경에 의존한다.
