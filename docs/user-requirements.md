# 사용자 요구사항과 결정

2026-10-07 기준 대화에서 반복해서 요청하거나 후속 요청으로 확정한 기준이다.
현재 구현 상세는 [현행 사양](spec.md), 다음 작업은 [작업 인계](handoff.md)를 따른다.
이 문서는 나중에 AI가 디자인 의도를 잃거나 완료한 작업을 되돌리지 않도록 남긴다.

## 디자인 방향

웹 관리 화면보다 게임다운 만화풍 UI를 원한다. 차분한 숲·초록 재질과 크림색 글자를 유지하고,
화려한 배경·파란 테두리·크고 하얀 시작 버튼·강한 입체감은 피한다.
캐릭터는 남자아이이며 최대 폭의 짧은 세로 화면에서도 얼굴과 몸이 보여야 한다.

초안 이미지와 실제 화면의 차이에 대한 지적이 반복됐다. CSS로 비슷한 사각형을 그리는 데 그치지 말고
승인된 그림의 버튼·아이콘을 실제 부품 이미지로 사용한다. 각 버튼의 클릭·포커스는 HTML 요소가 맡고
수치·내용·상태는 동적으로 표시한다. 전체 메뉴를 통이미지 한 장으로 만드는 방식은 최종 요청과 다르다.

승인 기준은 [시작 메뉴](design/approved-lobby.webp), [내부 메뉴](design/approved-menus.webp)다.
초기 [길드 시안](design/guild-lobby-concept.webp)과 [메뉴 탐색 시안](design/quest-menu-concepts.webp)은 제작 이력이다.

## 메뉴·화면·가독성

- 위쪽은 왼쪽 스토리 모드 지도, 오른쪽 붉은 1일 전투 버튼이다. 연습/전체 단어 도전은 그 아래, 상점/장비/통계/설정은 하단이다. 로비 터치에는 장착 무기의 이펙트를 표시한다.
- 새 단어 낙하전은 로비에서 진입한다. 탑뷰 공간에 영어·한국어 단어가 내려오고, 누른 단어의 보기를 아래에서 고른다. 정답 공격, 작은 보기 버튼, 시간에 따른 낙하 가속을 지원한다.
- 스토리·1일 전투 아이콘도 주변 생성 그림의 재질과 맞추고, 설정에서 모든 게임 진행을 확인 후 초기화할 수 있어야 한다.
- 시작 배경은 여러 장을 무작위로 고르고, 킹왕짱 타이틀의 6가지 순열도 바뀐다. 직전 배경/타이틀은 반복하지 않는다.
- 로비·게임·팝업은 같은 그림체와 색조를 쓴다. 공격하기는 붉은 계열. 적용·출력·마을로 등의 버튼에도 독립 이미지 바탕과 아이콘을 사용한다.
- 내부 메뉴의 중복 `< 뒤로`는 필요 없다. 마을로 버튼을 유지한다.
- 골드 영역은 5자리면 충분한 크기로 만들되 실제 값을 임의로 잘라 저장하지 않는다. 전투에서는 범위 표시(전체/Day) 바로 옆 같은 줄에 둔다.
- 전투 배경은 상단 제목·음악·나가기·전체화면 뒤까지 한 장으로 이어지게 확대한다. 조작 버튼과 다른 글자의 모양·위치는 유지한다.
- 문제 카드의 색은 녹색 답안 버튼과 구별하고 카드 안에는 실제 문제 단어·뜻만 둔다. 결과 화면의 글꼴·색과 배치를 다른 메뉴에 맞춘다.
- 철자 조합에는 답에 없는 흔한 글자 약 3개를 추가한다. 발음은 기존보다 두 배 크게 들리도록 하고 배경음악 일시정지를 유지한다.
- 스토리 지도는 생성형 이미지 초안을 먼저 만든다. 암시장 구매 버튼을 다른 이미지 버튼과 맞추고 구매 실패 시 비용만 차감되는 위험을 안내한다.
- 콤보 박스, 문제/정답 영역, 메뉴 제목/골드, 각 버튼의 패딩과 좌우 정렬이 프레임을 넘지 않게 한다.
- 밝은 배경 위의 밝은 글자를 없앤다. select의 선택 값과 펼친 option, 음악 1~20곡의 이름, 답안의 번호/단어를 모두 읽을 수 있어야 한다.
- 음악 ON/OFF는 실제 재생 상태에 맞추고 꺼졌을 때 사선이 있는 아이콘을 쓴다. 자동 재생 실패도 OFF다.

## 비율·전체화면

초기에 4:3~19.5:9 지원이라고 표현했지만 후속 설명은 **세로가 더 긴 최대 비율**이었다.
현행 해석은 가로:세로 최대 **3:4**, 긴 폰은 세로 공간을 쓰는 유동적 크기다.
로비와 게임에 같은 크기 계산을 적용한다. 데스크톱/가로 회전에서도 가운데 세로 프레임을 유지한다.

전체화면 버튼은 모든 화면에서 항상 같은 모서리에 있어야 한다. 현행은 게임 프레임 우상단이다.
브라우저 오른쪽 끝으로 나가거나 메뉴 제목·조작 버튼과 겹치면 안 된다. 이미지 모서리도 찌그러지거나 잘리지 않아야 한다.
팝업을 열어도 같은 버튼이 표시되고 동작해야 한다.

## 장비와 학습 게임의 확장

장비 화면의 오른손·왼손, 오른발·왼발은 각 쌍이 같은 행에 있어야 한다.
정면 캐릭터 기준 오른손은 화면 왼쪽이다. 별도 의미 없는 무기 슬롯 대신 실제 장착 슬롯을 명확히 안내한다.
장착 가능 위치·상점 설명·전투 동작·저장 복원을 같은 규칙으로 검증한다.

요청했던 확장 순서는 몬스터별 문제 → 복수 퀘스트 → 장비 역할 → 무기별 전투 모션이다. 모두 구현되어 있다.
모션은 단검·검·도끼·화염·얼음·번개·우주의 효과가 구별되어야 한다.
오른손 무기 형태를 왼손 속성이 덮어쓰지 않게 하고, 새 이미지도 기존 그림체에 맞춘다.

코드 수정 후 검증·리뷰·빌드·푸시·배포와 실제 반영 확인을 원한다. 새로운 작업의 배포 여부는 그때의 요청을 따른다.
Git 작성자·커미터 이름은 `obmaz`, 이메일은 `zambobmaz@gmail.com`을 사용한다. 기존 커밋의 이메일도 사용자 요청으로 교체했다. 이전 이력 정리 요청은 매 작업마다 이력을 다시 쓰라는 뜻이 아니다.

당분간 업데이트 계획이 없으므로 향후 AI가 읽을 현재 사양·구조·에셋·검증·미완성 제약을 저장소에 남기는 것이 이번 정리의 목적이다.
현재 추가 기능 개발을 예정하거나 승인한 것은 아니다.
